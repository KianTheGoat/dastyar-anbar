# دستیار انبار

پایهٔ یک داشبورد ساده برای فروشگاه‌های اینترنتی: تشخیص کمبود هر رنگ و سایز و
اولویت تأمین بر اساس تعداد فروش. حدها در سطح دسته‌بندی تنظیم می‌شوند.

**وضعیت فعلی: اسناد معماری و اسکلت قابل اجرا. سرویس تجاری آماده نیست.**

چهار سند اصلی: [Agent.md](Agent.md)، [Structure.md](Structure.md)،
[Workflow.md](Workflow.md)، [Rules.md](Rules.md).
`AGENTS.md` ورودی خودکار ابزارهای کدنویسی است.

## آماده‌شده

- React / TypeScript / Vite با پوستهٔ فارسی RTL، حالت خالی، راهنما، اطلاعیهٔ حریم
  خصوصی و شرایط استفاده، حالت روشن/تیره و پشتیبانی کاهش حرکت.
- FastAPI با health endpoint، محدودکردن Host، CORS مشخص و هدرهای امنیتی API.
- منطق خالص طبقه‌بندی و اولویت تأمین، همراه آزمون‌های مرزی.
- مدل‌های PostgreSQL و migration اولیه با کلیدهای خارجی مشترک فروشگاه.
- تنظیمات PostgreSQL محلی، قفل وابستگی‌ها و CI.

## مرحلهٔ بعد، پیش از فروش

ورود و نشست کاربران، دسترسی فروشگاه، ورود CSV/XLSX و پیش‌نمایش، اتصال خصوصی
گوگل‌شیت، گزارش دادهٔ واقعی، خروجی، تنظیم دسته‌بندی و دستیار مبتنی بر نتایج.
این قابلیت‌ها در اسناد تعریف شده‌اند و هنوز پیاده‌سازی نشده‌اند.
هویت گرداننده، تماس حریم خصوصی، محل میزبانی، دورهٔ نگهداری، حذف حساب، شرایط
تجاری و کنترل‌های انتشار باید قبل از جمع‌آوری داده کامل و بررسی شوند.

## اجرا در Windows / PowerShell

نیاز توسعه‌دهنده: Python 3.12-3.14، Node.js 24 و برای دیتابیس Docker فعال.
کاربر نهایی سرویس آینده فقط مرورگر نیاز دارد.

بک‌اند:

```powershell
cd apps/api
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-dev.lock
.\.venv\Scripts\python -m pip install -e . --no-deps
.\.venv\Scripts\python -m pytest
.\.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

فرانت‌اند، در ترمینال دیگر از ریشهٔ پروژه:

```powershell
cd apps/web
npm ci
npm run build
npm run dev -- --host 127.0.0.1
```

رابط: http://127.0.0.1:5173، سلامت: http://127.0.0.1:8000/api/health.
برای shell و health، دیتابیس لازم نیست؛ هیچ داده‌ای ذخیره نمی‌شود.

اگر اجرای کتابخانه‌های بومی Python با سیاست امنیتی Windows مسدود بود، تنظیمات
امنیتی را تغییر ندهید. API را با کانتینر رسمی اجرا کنید:

```powershell
docker build -t dastyar-anbar-api apps/api
docker run --rm -p 127.0.0.1:8000:8000 dastyar-anbar-api
```

این تصویر با کاربر غیر root اجرا می‌شود و فقط وابستگی‌های runtime را دارد.
اجرای API به تنهایی داده‌ای به دیتابیس نمی‌نویسد.

دیتابیس، از ریشهٔ پروژه: `.env.example` را به `.env` کپی کنید، رمز محلی تعیین
کنید و `docker compose --env-file .env -f infra/compose.yaml up -d` را اجرا کنید.
در محیط بک‌اند `DATABASE_URL` را مطابق مثال تنظیم کنید، سپس
`python -m alembic upgrade head` و `python -m alembic check` را با Python همان
venv اجرا کنید. دیتابیس فقط روی loopback منتشر می‌شود.

## یادداشت امنیت و حریم خصوصی

این مخزن عمومی است؛ اطلاعات واقعی، فایل مشتری و credential را commit نکنید.
پوستهٔ فعلی کوکی تنظیم نمی‌کند و ابزار تحلیل رفتار ندارد. اطلاعیهٔ موجود
فقط رفتار همین نسخه را توضیح می‌دهد؛ ادعای انطباق کامل قانونی ندارد.
کنترل‌های برنامه‌ریزی‌شده و الزامات پیش از انتشار در Rules.md و Workflow.md هستند.

کدهای این مخزن مجوز متن‌باز اضافه ندارند. عمومی‌بودن مخزن به معنی اعطای
مجوز بازنشر یا استفادهٔ تجاری نیست؛ انتخاب مجوز با مالک پروژه است.

## بررسی انجام‌شده، ۱۲ اکتبر ۲۰۲۶

- ۲۷ آزمون در Python 3.13 / Linux و PostgreSQL 17 موفق شدند.
- migration اولیه اعمال شد و بررسی Alembic اختلافی با مدل‌ها پیدا نکرد.
- build تولیدی React/TypeScript موفق بود؛ npm audit و pip-audit مورد شناخته‌شده‌ای گزارش نکردند.
- مسیرهای حریم خصوصی و شرایط استفاده، RTL، عرض‌های موبایل/تبلت و بستن دستیار با Escape بررسی شدند.
- ۱۶ جفت رنگ متن/پس‌زمینه در حالت روشن/تیره حداقل نسبت 4.5:1 دارند.
- آزمون native روی Windows با محدودیت Application Control روبه‌رو شد؛ مسیر Docker بدون تغییر سیاست امنیتی اجرا شد.

این بررسی‌ها مربوط به اسکلت فعلی‌اند و جایگزین کنترل‌های انتشار سرویس آینده نیستند.
